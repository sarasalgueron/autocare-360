3. Que significa realmente CRUD sobre HTTP
CRUD
HTTP
Intencion
Idempotencia didactica
Read
GET
Leer sin modificar el recurso.
Si, repetir debe conservar el mismo efecto. 
Create
POST
Crear un nuevo recurso bajo la coleccion.
No necesariamente; repetir puede duplicar.
Update
PUT
Reemplazar/actualizar la representacion indicada.
Si, repetir el mismo PUT debe dejar el mismo estado.
Delete
DELETE
Eliminar el recurso indicado.
Si respecto del estado final: queda eliminado.

Defensa: El estudiante no debe responder que PUT y POST son "casi lo mismo". POST crea bajo una coleccion; PUT actua sobre un recurso identificado y su semantica es idempotente.

4. Contratos TypeScript para crear y actualizar
features/clientes/types/ClienteRequests.ts
import type { Cliente } from '../models/Cliente';

export type ClienteCreateRequest = Omit<Cliente, 'id'>;
export type ClienteUpdateRequest = Omit<Cliente, 'id'>;

Aunque ambos tipos tengan hoy la misma forma, se nombran por intencion. Si manana el backend exige campos diferentes para crear y editar, el cambio queda localizado.
features/clientes/services/clienteService.ts
import { apiFetch } from '../../../api/apiClient';
import type { Cliente } from '../models/Cliente';
import type {
  ClienteCreateRequest,
  ClienteUpdateRequest,
} from '../types/ClienteRequests';

export const clienteService = {
  listar(signal?: AbortSignal): Promise<Cliente[]> {
    return apiFetch<Cliente[]>('/clientes', { signal });
  },

  obtenerPorId(id: number, signal?: AbortSignal): Promise<Cliente> {
    return apiFetch<Cliente>(`/clientes/${id}`, { signal });
  },

  crear(data: ClienteCreateRequest): Promise<Cliente> {
    return apiFetch<Cliente>('/clientes', {
      method: 'POST',
      body: JSON.stringify(data),
    });
  },

  actualizar(id: number, data: ClienteUpdateRequest): Promise<Cliente> {
    return apiFetch<Cliente>(`/clientes/${id}`, {
      method: 'PUT',
      body: JSON.stringify(data),
    });
  },

  eliminar(id: number): Promise<void> {
    return apiFetch<void>(`/clientes/${id}`, {
      method: 'DELETE',
    });
  },
};

Diseño: El componente no construye URLs ni conoce headers. Expresa intenciones: clienteService.actualizar(7, data) o clienteService.eliminar(7).

5. Convertir ClienteTable en componente con acciones
ClienteTable.tsx - props de eventos
import type { Cliente } from '../models/Cliente';

interface ClienteTableProps {
  clientes: Cliente[];
  onEdit: (id: number) => void;
  onDelete: (cliente: Cliente) => void;
  deletingId?: number | null;
}

export default function ClienteTable({
  clientes,
  onEdit,
  onDelete,
  deletingId,
}: ClienteTableProps) {
  return (
    <table className="data-table">
      <thead>
        <tr>
          <th>ID</th><th>Nombre</th><th>Documento</th>
          <th>Email</th><th>Estado</th><th>Acciones</th>
        </tr>
      </thead>
      <tbody>
        {clientes.map((cliente) => (
          <tr key={cliente.id}>
            <td>{cliente.id}</td>
            <td>{cliente.nombre} {cliente.apellido}</td>
            <td>{cliente.documento}</td>
            <td>{cliente.email}</td>
            <td>{cliente.activo ? 'Activo' : 'Inactivo'}</td>
            <td className="actions-cell">
              <button type="button" onClick={() => onEdit(cliente.id)}>
                Editar
              </button>
              <button
                type="button"
                onClick={() => onDelete(cliente)}
                disabled={deletingId === cliente.id}
              >
                {deletingId === cliente.id ? 'Eliminando...' : 'Eliminar'}
              </button>
            </td>
          </tr>
        ))}
      </tbody>
    </table>
  );
}

Separacion: La tabla solicita una accion mediante callbacks. No debe importar clienteService ni decidir como se actualiza PostgreSQL.

6. GET/{id}: seleccionar un Cliente para editar
Aunque la fila ya contiene datos, en esta guia usamos GET/{id} para practicar el endpoint y obtener una copia actual del recurso antes de editar.
ClientesPage.tsx - cargar detalle antes de editar
const [editingCliente, setEditingCliente] = useState<Cliente | null>(null);
const [loadingDetail, setLoadingDetail] = useState(false);

const handleEdit = async (id: number) => {
  try {
    setLoadingDetail(true);
    setError('');
    const cliente = await clienteService.obtenerPorId(id);
    setEditingCliente(cliente);
  } catch (err) {
    setError(err instanceof Error ? err.message : 'No se pudo cargar el cliente');
  } finally {
    setLoadingDetail(false);
  }
};

Si el recurso ya no existe, el backend puede responder 404 y no se debe abrir un formulario con datos viejos.
En una aplicacion grande el listado puede devolver un resumen y GET/{id} un detalle mas completo.
Si el proyecto garantiza que la fila contiene todo y no necesita refrescar, se puede editar directamente con el objeto de la fila; aqui se practica deliberadamente GET/{id}.
7. Un solo ClienteForm para Crear y Editar
ClienteForm.tsx - modo create/edit
interface ClienteFormProps {
  cliente?: Cliente | null;
  onSaved: (cliente: Cliente, mode: 'create' | 'edit') => void;
  onCancelEdit?: () => void;
}

const initialClienteForm: ClienteFormData = {
  nombre: '',
  apellido: '',
  documento: '',
  telefono: '',
  email: '',
  activo: true,
};

export default function ClienteForm({
  cliente,
  onSaved,
  onCancelEdit,
}: ClienteFormProps) {
  const [formData, setFormData] = useState(initialClienteForm);
  const [errors, setErrors] = useState<Record<string, string>>({});
  const [saving, setSaving] = useState(false);
  const [apiError, setApiError] = useState('');

  const isEditing = cliente != null;

  useEffect(() => {
    if (cliente) {
      setFormData({
        nombre: cliente.nombre,
        apellido: cliente.apellido,
        documento: cliente.documento,
        telefono: cliente.telefono,
        email: cliente.email,
        activo: cliente.activo,
      });
    } else {
      setFormData(initialClienteForm);
    }
    setErrors({});
    setApiError('');
  }, [cliente]);

  // ... handleChange y validarCliente de la Guia 04
}

Por que useEffect aqui: El Effect sincroniza el estado editable del formulario cuando cambia la prop cliente. No realiza una mutacion HTTP automatica.

8. POST o PUT segun el modo del formulario
ClienteForm.tsx - handleSubmit
const handleSubmit = async (e: FormEvent<HTMLFormElement>) => {
  e.preventDefault();
  setApiError('');

  const validationErrors = validarCliente(formData);
  setErrors(validationErrors);
  if (Object.keys(validationErrors).length > 0) return;

  const payload = {
    nombre: formData.nombre.trim(),
    apellido: formData.apellido.trim(),
    documento: formData.documento.trim(),
    telefono: formData.telefono.trim(),
    email: formData.email.trim().toLowerCase(),
    activo: formData.activo,
  };

  try {
    setSaving(true);

    if (cliente) {
      const actualizado = await clienteService.actualizar(cliente.id, payload);
      onSaved(actualizado, 'edit');
    } else {
      const creado = await clienteService.crear(payload);
      onSaved(creado, 'create');
      setFormData(initialClienteForm);
    }
  } catch (err) {
    setApiError(err instanceof Error ? err.message : 'No se pudo guardar');
  } finally {
    setSaving(false);
  }
};

ClienteForm.tsx - controles del modo
<h2>{isEditing ? `Editar cliente #${cliente.id}` : 'Nuevo cliente'}</h2>

<button type="submit" disabled={saving}>
  {saving
    ? 'Guardando...'
    : isEditing
      ? 'Actualizar cliente'
      : 'Crear cliente'}
</button>

{isEditing && (
  <button type="button" onClick={onCancelEdit} disabled={saving}>
    Cancelar edicion
  </button>
)}

Regla: Nunca decidir entre POST y PUT mirando si el nombre del boton dice "Guardar". La decision depende de si existe un recurso persistido identificado por id.

9. Sincronizar ClientesPage despues de Crear o Editar
ClientesPage.tsx - actualizar estado local
const handleSaved = (saved: Cliente, mode: 'create' | 'edit') => {
  setClientes((prev) => {
    if (mode === 'create') {
      return [...prev, saved];
    }

    return prev.map((cliente) =>
      cliente.id === saved.id ? saved : cliente,
    );
  });

  setEditingCliente(null);
};

Hay dos estrategias validas para sincronizar la interfaz despues de una mutacion:
Estrategia
Ventaja
Costo/consideracion
Actualizar estado local
Rapida; evita GET adicional.
Debe usar la respuesta real del backend y mantener la logica correcta.
Volver a listar
Simple y confirma el estado servidor.
Hace una peticion GET adicional.

Esta guia: Usaremos actualizacion local con el objeto devuelto por POST/PUT. En situaciones complejas puede ser preferible invalidar/refrescar datos.

10. DELETE con confirmacion y manejo de relacion 1:N
ClientesPage.tsx - eliminar
const [deletingId, setDeletingId] = useState<number | null>(null);

const handleDelete = async (cliente: Cliente) => {
  const confirmed = window.confirm(
    `¿Eliminar a ${cliente.nombre} ${cliente.apellido}?`,
  );

  if (!confirmed) return;

  try {
    setDeletingId(cliente.id);
    setError('');
    await clienteService.eliminar(cliente.id);

    setClientes((prev) =>
      prev.filter((item) => item.id !== cliente.id),
    );

    if (editingCliente?.id === cliente.id) {
      setEditingCliente(null);
    }
  } catch (err) {
    setError(err instanceof Error ? err.message : 'No se pudo eliminar');
  } finally {
    setDeletingId(null);
  }
};

DELETE y body: En el caso normal, el id viaja en la URL y no necesitamos enviar body. Un DELETE exitoso puede devolver 204 No Content; apiClient ya contempla ese caso.

Relacion 1:N: Si Cliente tiene Vehiculos asociados, el backend puede impedir el DELETE por integridad referencial o regla de negocio y responder, por ejemplo, 409. React debe mostrar el error; NO debe ocultarlo borrando la fila de la UI.

11. Integracion de ClientesPage
ClientesPage.tsx - estructura final
export default function ClientesPage() {
  const [clientes, setClientes] = useState<Cliente[]>([]);
  const [editingCliente, setEditingCliente] = useState<Cliente | null>(null);
  const [loading, setLoading] = useState(true);
  const [loadingDetail, setLoadingDetail] = useState(false);
  const [deletingId, setDeletingId] = useState<number | null>(null);
  const [error, setError] = useState('');

  useEffect(() => {
    const controller = new AbortController();

    const load = async () => {
      try {
        setLoading(true);
        const data = await clienteService.listar(controller.signal);
        setClientes(data);
      } catch (err) {
        if (!(err instanceof DOMException && err.name === 'AbortError')) {
          setError(err instanceof Error ? err.message : 'Error al listar');
        }
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    };

    void load();
    return () => controller.abort();
  }, []);

  // handleEdit, handleSaved y handleDelete definidos en esta guia

  if (loading) return <div className="state-card">Cargando clientes...</div>;

  return (
    <section className="page-stack">
      <header>
        <h1>Clientes</h1>
        <p>CRUD completo conectado con Spring Boot.</p>
      </header>

      {error && <div className="state-card error">{error}</div>}
      {loadingDetail && <div className="state-card">Cargando detalle...</div>}

      <ClienteForm
        cliente={editingCliente}
        onSaved={handleSaved}
        onCancelEdit={() => setEditingCliente(null)}
      />

      <ClienteTable
        clientes={clientes}
        onEdit={handleEdit}
        onDelete={handleDelete}
        deletingId={deletingId}
      />
    </section>
  );
}

13. Flujos que el estudiante debe poder dibujar
Accion
Flujo resumido
Listar
Page -> clienteService.listar -> GET -> Controller -> Service -> Repository -> SELECT -> JSON -> setClientes.
Editar
Click -> GET/{id} -> JSON -> editingCliente -> ClienteForm carga datos -> PUT -> UPDATE -> respuesta -> map() reemplaza fila.
Crear
Submit -> validacion -> POST -> INSERT -> objeto con id -> array agrega fila.
Eliminar
Click -> confirm -> DELETE/{id} -> regla/integridad -> 204 -> filter() quita fila.

Defensa extrema: El alumno debe poder señalar en que momento existe un objeto JavaScript, cuando viaja JSON, donde actua JPA y cuando React vuelve a renderizar.
