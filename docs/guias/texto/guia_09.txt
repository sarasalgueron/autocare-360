4. Button reutilizable y variantes
components/ui/Button.tsx
type ButtonVariant = 'primary' | 'secondary' | 'danger' | 'ghost';

type ButtonProps = React.ButtonHTMLAttributes<HTMLButtonElement> & {
  variant?: ButtonVariant;
  loading?: boolean;
};

export function Button({
  variant = 'primary',
  loading = false,
  disabled,
  children,
  ...props
}: ButtonProps) {
  return (
    <button
      className={`btn btn--${variant}`}
      disabled={disabled || loading}
      {...props}
    >
      {loading ? 'Procesando...' : children}
    </button>
  );
}

Extender ButtonHTMLAttributes permite conservar onClick, type, title, aria-label y otras props nativas.
variant controla presentacion; no debe codificar reglas de negocio.
loading evita dobles envios y comunica que hay una operacion en curso.
5. SearchInput y SelectFilter
SearchInput.tsx
type SearchInputProps = {
  value: string;
  onChange: (value: string) => void;
  placeholder?: string;
};

export function SearchInput({ value, onChange, placeholder = 'Buscar...' }: SearchInputProps) {
  return (
    <label className="field">
      <span className="field__label">Busqueda</span>
      <input
        type="search"
        value={value}
        onChange={(e) => onChange(e.target.value)}
        placeholder={placeholder}
      />
    </label>
  );
}

SelectFilter.tsx
type Option = { value: string; label: string };

type SelectFilterProps = {
  label: string;
  value: string;
  options: Option[];
  onChange: (value: string) => void;
};

export function SelectFilter({ label, value, options, onChange }: SelectFilterProps) {
  return (
    <label className="field">
      <span className="field__label">{label}</span>
      <select value={value} onChange={(e) => onChange(e.target.value)}>
        {options.map((option) => (
          <option key={option.value} value={option.value}>{option.label}</option>
        ))}
      </select>
    </label>
  );
}

6. Estado fuente y estado derivado
No copie filteredClientes a useState si puede calcularse desde clientes + search + activoFilter. La lista filtrada es un dato derivado. Guardarla tambien como estado crea dos fuentes de verdad que pueden desincronizarse.
Valor
Guardar en useState
Motivo

Si
Proviene del backend y cambia con CRUD
search
Si
Lo controla el usuario
activoFilter
Si
Lo controla el usuario
filteredClientes
No
Se calcula desde otros valores

Si
Seleccion actual del usuario

7. Busqueda y filtros combinados
Filtro compuesto de Clientes
const [search, setSearch] = useState('');
const [activoFilter, setActivoFilter] = useState<'all' | 'active' | 'inactive'>('all');

const filteredClientes = clientes.filter((cliente) => {
  const term = search.trim().toLowerCase();
  const matchesText = !term ||
    cliente.nombre.toLowerCase().includes(term) ||
    cliente.apellido.toLowerCase().includes(term) ||
    cliente.documento.toLowerCase().includes(term) ||
    cliente.email.toLowerCase().includes(term);

  const matchesStatus =
    activoFilter === 'all' ||
    (activoFilter === 'active' && cliente.activo) ||
    (activoFilter === 'inactive' && !cliente.activo);

  return matchesText && matchesStatus;
});

El operador AND aparece en el return final: el registro debe cumplir busqueda textual y estado. Dentro de matchesText usamos OR porque cualquiera de los campos puede coincidir.
8. useMemo: optimizacion, no requisito funcional
Memoizacion opcional
const filteredClientes = useMemo(() => {
  return clientes.filter((cliente) => {
    // calculo puro
    return matchesSearch(cliente, search) && matchesStatus(cliente, activoFilter);
  });
}, [clientes, search, activoFilter]);

Importante:  useMemo debe usarse como optimizacion de un calculo puro. El codigo debe ser correcto aun sin useMemo. Para colecciones pequenas, filter() directo suele ser suficiente y mas simple.

10. Componente Pagination
Pagination.tsx
type PaginationProps = {
  page: number;
  totalPages: number;
  onPageChange: (page: number) => void;
};

export function Pagination({ page, totalPages, onPageChange }: PaginationProps) {
  return (
    <nav className="pagination" aria-label="Paginacion">
      <Button variant="ghost" disabled={page <= 1} onClick={() => onPageChange(page - 1)}>
        Anterior
      </Button>
      <span>Pagina {page} de {totalPages}</span>
      <Button variant="ghost" disabled={page >= totalPages} onClick={() => onPageChange(page + 1)}>
        Siguiente
      </Button>
    </nav>
  );
}

No permita pagina 0 ni pagina mayor a totalPages. Al eliminar el ultimo elemento de una pagina, ajuste la pagina si quedo fuera de rango.

12. Modal reutilizable con <dialog>
Modal.tsx
import { useEffect, useRef, type ReactNode } from 'react';

type ModalProps = {
  open: boolean;
  title: string;
  children: ReactNode;
  onClose: () => void;
};

export function Modal({ open, title, children, onClose }: ModalProps) {
  const ref = useRef<HTMLDialogElement>(null);

  useEffect(() => {
    const dialog = ref.current;
    if (!dialog) return;
    if (open && !dialog.open) dialog.showModal();
    if (!open && dialog.open) dialog.close();
  }, [open]);

  return (
    <dialog ref={ref} className="modal" onCancel={onClose} onClose={onClose}>
      <header className="modal__header">
        <h2>{title}</h2>
        <button aria-label="Cerrar" onClick={onClose}>×</button>
      </header>
      {children}
    </dialog>
  );
}

Ventaja del <dialog> nativo:  showModal() coloca el dialogo en la capa superior, bloquea la interaccion con el contenido externo y ofrece comportamiento de teclado que seria necesario recrear manualmente en un modal basado solo en div.

13. ConfirmDialog para DELETE
ConfirmDialog.tsx
type ConfirmDialogProps = {
  open: boolean;
  title: string;
  message: string;
  confirming?: boolean;
  onConfirm: () => void;
  onCancel: () => void;
};

export function ConfirmDialog(props: ConfirmDialogProps) {
  return (
    <Modal open={props.open} title={props.title} onClose={props.onCancel}>
      <p>{props.message}</p>
      <div className="modal__actions">
        <Button variant="secondary" onClick={props.onCancel}>Cancelar</Button>
        <Button variant="danger" loading={props.confirming} onClick={props.onConfirm}>
          Eliminar
        </Button>
      </div>
    </Modal>
  );
}

La confirmacion no conoce Cliente ni Vehiculo. La Page guarda el id pendiente de eliminar y decide que service ejecutar al confirmar.
14. Integracion en ClientesPage
Estado de coordinacion de ClientesPage
const [search, setSearch] = useState('');
const [status, setStatus] = useState('all');
const [page, setPage] = useState(1);
const [pendingDelete, setPendingDelete] = useState<Cliente | null>(null);

const filtered = clientes.filter((cliente) =>
  matchesCliente(cliente, search, status)
);
const totalPages = Math.max(1, Math.ceil(filtered.length / PAGE_SIZE));
const visible = filtered.slice((page - 1) * PAGE_SIZE, page * PAGE_SIZE);

async function confirmDelete() {
  if (!pendingDelete) return;
  await remove(pendingDelete.id);
  setPendingDelete(null);
}

SearchInput actualiza search.
SelectFilter actualiza status.
La Page calcula filtered y visible.
ClienteTable recibe solo visible.
Al pulsar Eliminar se asigna pendingDelete; no se elimina todavia.
ConfirmDialog llama confirmDelete.
El hook/service elimina; al cambiar clientes se recalcula automaticamente la lista visible.

Filtros combinados de Vehiculos
const [search, setSearch] = useState('');
const [clienteFilter, setClienteFilter] = useState('all');
const [status, setStatus] = useState('all');

const filteredVehiculos = vehiculos.filter((vehiculo) => {
  const owner = clientesById.get(vehiculo.clienteId);
  const text = `${vehiculo.placa} ${vehiculo.marca} ${vehiculo.modelo} ${owner?.nombre ?? ''} ${owner?.apellido ?? ''}`
    .toLowerCase();

  const matchesText = text.includes(search.trim().toLowerCase());
  const matchesOwner = clienteFilter === 'all' || vehiculo.clienteId === Number(clienteFilter);
  const matchesStatus = status === 'all' || (status === 'active' ? vehiculo.activo : !vehiculo.activo);

  return matchesText && matchesOwner && matchesStatus;
});

18. Cuando la paginacion debe moverse al backend
La paginacion cliente es apropiada si ya se cargaron todos los registros y el volumen es moderado. Con miles o millones de registros, descargar todo para despues ocultar la mayoria desperdicia red, memoria y tiempo.
Cliente
Servidor
GET /clientes y luego slice()
GET /clientes?page=0&size=20&search=ana&activo=true
Todos los registros llegan al navegador
Solo llega la pagina solicitada
Simple para conjuntos pequenos
Escalable para grandes volumenes
totalPages calculado localmente
Backend devuelve totalElements/totalPages o metadatos equivalentes

Preparacion para evolucion:  La interfaz Pagination puede mantenerse aunque la fuente de datos cambie de paginacion cliente a servidor. Cambia quien calcula y obtiene la pagina, no necesariamente la UI.
