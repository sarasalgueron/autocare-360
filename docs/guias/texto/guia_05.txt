Lectura basica
const API_URL = import.meta.env.VITE_API_URL;

  throw new Error('Falta configurar VITE_API_URL');

Seguridad: Una variable VITE_ termina en el bundle del frontend y puede ser leida por el usuario. Sirve para URLs/configuracion publica; NO para contraseñas, claves privadas, tokens secretos ni credenciales de base de datos.

6. Habilitar CORS en Spring Boot para desarrollo
React/Vite y Spring Boot normalmente se ejecutan en origenes distintos durante desarrollo. El backend debe autorizar explicitamente el origen del frontend.
Ejemplo global de CORS en Spring MVC
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOrigins("http://localhost:5173")
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*");
    }
}

Si Vite arranco en otro puerto, allowedOrigins debe coincidir con el origen real del navegador.
En produccion se autoriza el dominio real del frontend, no localhost.
No confundir CORS con autenticacion: CORS decide que origen del navegador puede llamar; no identifica al usuario.
Si mas adelante se usan cookies/credenciales, la configuracion requiere decisiones adicionales y no conviene combinar credenciales con origen wildcard.
7. Crear apiClient.ts: una sola puerta HTTP
src/api/apiClient.ts
const API_URL = import.meta.env.VITE_API_URL;

export class ApiError extends Error {
  constructor(
    public status: number,
    message: string,
  ) {
    super(message);
    this.name = 'ApiError';
  }
}

export async function apiFetch<T>(
  endpoint: string,
  options: RequestInit = {},
): Promise<T> {
  if (!API_URL) {
    throw new Error('Falta VITE_API_URL');
  }

  const headers = new Headers(options.headers);
  if (options.body && !headers.has('Content-Type')) {
    headers.set('Content-Type', 'application/json');
  }

  const response = await fetch(`${API_URL}${endpoint}`, {
    ...options,
    headers,
  });

  if (!response.ok) {
    const detail = await response.text();
    throw new ApiError(
      response.status,
      detail || response.statusText || 'Error HTTP',
    );
  }

  if (response.status === 204) {
    return undefined as T;
  }

  return response.json() as Promise<T>;
}

Que centralizamos: URL base, cabeceras JSON, verificacion response.ok, conversion de errores HTTP y lectura JSON. Los services dejan de repetir esta logica.

8. Contratos de request y services

Importante: Omit<..., id> es valido solo si el JSON del backend coincide con el modelo frontend menos id. Si Swagger usa un DTO distinto, cree una interface exacta para ese DTO.

features/clientes/services/clienteService.ts
import { apiFetch } from '../../../api/apiClient';
import type { Cliente } from '../models/Cliente';
import type { ClienteCreateRequest } from '../types/ClienteCreateRequest';

export const clienteService = {
  listar(signal?: AbortSignal): Promise<Cliente[]> {
    return apiFetch<Cliente[]>('/clientes', { signal });
  },

  crear(data: ClienteCreateRequest): Promise<Cliente> {
    return apiFetch<Cliente>('/clientes', {
      method: 'POST',
      body: JSON.stringify(data),
    });
  },
};

features/vehiculos/services/vehiculoService.ts
import { apiFetch } from '../../../api/apiClient';
import type { Vehiculo } from '../models/Vehiculo';
import type { VehiculoCreateRequest } from '../types/VehiculoCreateRequest';

export const vehiculoService = {
  listar(signal?: AbortSignal): Promise<Vehiculo[]> {
    return apiFetch<Vehiculo[]>('/vehiculos', { signal });
  },

  crear(data: VehiculoCreateRequest): Promise<Vehiculo> {
    return apiFetch<Vehiculo>('/vehiculos', {
      method: 'POST',
      body: JSON.stringify(data),
    });
  },
};

9. Primer GET real: listar Clientes
Ahora ClientesPage deja de usar clientesMock. El componente tiene tres estados independientes: datos, cargando y error.
ClientesPage.tsx - reemplazo de datos mock
import { useEffect, useState } from 'react';
import ClienteTable from '../features/clientes/components/ClienteTable';
import { clienteService } from '../features/clientes/services/clienteService';
import type { Cliente } from '../features/clientes/models/Cliente';

export default function ClientesPage() {
  const [clientes, setClientes] = useState<Cliente[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState('');

  useEffect(() => {
    const controller = new AbortController();

    const cargarClientes = async () => {
      try {
        setLoading(true);
        setError('');
        const data = await clienteService.listar(controller.signal);
        setClientes(data);
      } catch (err) {
        if (err instanceof DOMException && err.name === 'AbortError') return;
        setError(err instanceof Error ? err.message : 'Error inesperado');
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    };

    void cargarClientes();
    return () => controller.abort();
  }, []);

  if (loading) return <div className="state-card">Cargando clientes...</div>;
  if (error) return <div className="state-card error">{error}</div>;

  return <ClienteTable clientes={clientes} />;
}

11. Vehiculo y la relacion Cliente 1:N
El formulario de Vehiculo ya no debe obtener propietarios desde clientesMock. Debe cargar clientes reales y enviar la referencia en el formato que el backend espera.
VehiculoForm/Page: cargar propietarios reales
const [clientes, setClientes] = useState<Cliente[]>([]);

useEffect(() => {
  const controller = new AbortController();

  void clienteService.listar(controller.signal)
    .then((data) => setClientes(data.filter((c) => c.activo)))
    .catch((err) => {
      if (!(err instanceof DOMException && err.name === 'AbortError')) {
        console.error(err);
      }
    });

  return () => controller.abort();
}, []);

POST Vehiculo si Swagger recibe clienteId
const payload = {
  placa: formData.placa.trim().toUpperCase(),
  marca: formData.marca.trim(),
  modelo: formData.modelo.trim(),
  anio: Number(formData.anio),
  color: formData.color.trim(),
  clienteId: Number(formData.clienteId),

Mapeo alternativo segun contrato real
// Variante SOLO si Swagger muestra que el backend espera un objeto Cliente:
const payload = {
  placa: formData.placa.trim().toUpperCase(),
  marca: formData.marca.trim(),
  modelo: formData.modelo.trim(),
  anio: Number(formData.anio),
  color: formData.color.trim(),
  cliente: { id: Number(formData.clienteId) },
  activo: formData.activo,
};

Defensa 1:N: La relacion no se “crea” en React. React selecciona el cliente y envia una referencia. El backend/JPA valida y persiste la asociacion en la base de datos.

13. Diagnostico con DevTools + Swagger
1. Confirmar primero en Swagger que GET/POST funcionan y observar JSON exacto.
2. Abrir DevTools -> Network y ejecutar la accion desde React.
3. Revisar Request URL, Method, Status Code, Request Payload y Response.
4. Si no aparece ninguna peticion, el problema esta antes de fetch: evento/ruta/codigo.
5. Si aparece CORS, revisar origen permitido por Spring.
6. Si hay 404, comparar endpoint frontend con Swagger.
7. Si hay 400, comparar JSON enviado con el DTO/record esperado.
8. Si hay 500, revisar logs de Spring Boot; no “arreglar” React a ciegas.
9. Si hay 200 pero la UI falla, inspeccionar la forma real del JSON y el tipado frontend.

Ejemplo opcional - NO es necesario migrar esta guia
// Equivalente conceptual con Axios (opcional)
import axios from 'axios';

const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL,
});

const { data } = await api.get<Cliente[]>('/clientes');

Decision pedagogica: Usamos fetch primero porque obliga a comprender Response, status, headers y JSON. Cuando esos conceptos estan claros, Axios se aprende como una capa de conveniencia.
