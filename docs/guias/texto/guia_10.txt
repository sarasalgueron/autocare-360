4. Dashboard ejecutivo
El Dashboard no crea una nueva fuente de verdad. Consume las colecciones ya disponibles y deriva metricas. Para conjuntos grandes, estas metricas deben migrar a endpoints agregados del backend.
src/components/ui/MetricCard.tsx
type MetricCardProps = {
  label: string;
  value: number;
  helper?: string;
};

export function MetricCard({ label, value, helper }: MetricCardProps) {
  return (
    <article className="metric-card">
      <span>{label}</span>
      <strong>{value}</strong>
      {helper && <small>{helper}</small>}
    </article>
  );
}

DashboardPage: composicion de hooks y metricas
export function DashboardPage() {
  const clientes = useClientes();
  const vehiculos = useVehiculos();

  const loading = clientes.loading || vehiculos.loading;
  const error = clientes.error ?? vehiculos.error;

  const metrics = {
    clientesTotal: clientes.data.length,
    clientesActivos: clientes.data.filter(c => c.activo).length,
    vehiculosTotal: vehiculos.data.length,
    vehiculosActivos: vehiculos.data.filter(v => v.activo).length,
  };

  if (loading) return <p>Cargando dashboard...</p>;
  if (error) return <p role="alert">{error}</p>;

  return <DashboardMetrics metrics={metrics} />;
}

Importante:  No guardar clientesActivos o vehiculosTotal en useState si pueden calcularse desde data. Son estado derivado.

No confundir:  Una Error Boundary no reemplaza try/catch en fetch. React documenta que las Error Boundaries no capturan errores asincronos generales ni errores normales de event handlers.

7. ErrorBoundary de React
src/app/AppErrorBoundary.tsx
import React from 'react';

type Props = { children: React.ReactNode };
type State = { hasError: boolean };

export class AppErrorBoundary extends React.Component<Props, State> {
  state: State = { hasError: false };

  static getDerivedStateFromError(): State {
    return { hasError: true };
  }

  componentDidCatch(error: unknown, info: React.ErrorInfo) {
    console.error('Render error', error, info.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return <main role="alert"><h1>La interfaz tuvo un problema.</h1></main>;
    }
    return this.props.children;
  }
}

main.tsx
createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <AppErrorBoundary>
      <BrowserRouter>
        <App />
      </BrowserRouter>
    </AppErrorBoundary>
  </StrictMode>
);

19. BrowserRouter y fallback SPA
Con BrowserRouter, una URL como `/vehiculos` debe devolver `index.html` cuando se solicita directamente al servidor estatico. Si el servidor intenta buscar un archivo fisico `/vehiculos`, una recarga puede producir 404.
Ejemplo conceptual de Nginx
server {
  listen 80;
  server_name parkflow360.example.com;
  root /var/www/parkflow360/dist;

  location / {
    try_files $uri $uri/ /index.html;
  }
}

Prueba obligatoria:  Abrir /clientes, presionar F5 y comprobar que la SPA vuelve a cargar. Repetir con /vehiculos.

20. CORS en produccion
En desarrollo el origen suele ser `http://localhost:5173`. En produccion debe autorizarse el origen real del frontend. CORS es una politica del navegador; Postman puede seguir funcionando aunque el navegador bloquee la respuesta.
Ejemplo Spring Boot para produccion
@Configuration
public class CorsConfig implements WebMvcConfigurer {
  @Override
  public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/api/**")
      .allowedOrigins("https://parkflow360.example.com")
      .allowedMethods("GET", "POST", "PUT", "DELETE");
  }
}
