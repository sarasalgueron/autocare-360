1. Propósito y resultado esperado
En la Guía 02 se construyó la navegación de ParkFlow360 y quedaron disponibles las rutas /clientes y /vehiculos. En esta guía esas páginas dejarán de ser simples pantallas vacías: comenzarán a representar información realista del dominio usando TypeScript, datos simulados y tablas reutilizables por feature.
Regla de esta guía:  todavía NO se llama al backend. El objetivo es dominar el modelo de datos del frontend, el tipado, las props y el renderizado de colecciones antes de introducir asincronía, HTTP y CORS.

Al finalizar, el estudiante debe poder ejecutar ParkFlow360 y observar un listado profesional de clientes y otro de vehículos. Además, debe explicar de dónde sale cada dato y cómo viaja desde un arreglo TypeScript hasta una fila HTML renderizada por React.
2. Competencias que debe demostrar el estudiante
Explicar la diferencia entre una entidad JPA del backend y un modelo o contrato TypeScript del frontend.
Crear interfaces TypeScript para Cliente y Vehiculo sin recurrir a any.
Tipar arreglos de datos simulados con Cliente[] y Vehiculo[].
Pasar información de una página a un componente mediante props.
Renderizar colecciones con map() y justificar el uso de una key estable.
Representar en el frontend la relación Cliente 1:N Vehiculo mediante clienteId.
Resolver visualmente estados activos/inactivos y listas vacías.
Explicar el flujo completo datos → props → map() → JSX → DOM.
3. Del modelo Java al modelo TypeScript
El backend y el frontend describen el mismo dominio, pero cumplen responsabilidades distintas. Una entidad Java puede incluir anotaciones JPA, relaciones, reglas de persistencia y detalles internos que React no necesita conocer. El frontend necesita un contrato de datos claro para trabajar de forma segura con TypeScript.
Concepto
Responsabilidad
Entidad Java / JPA
Representa persistencia y dominio del backend. Puede tener @Entity, @Id, @OneToMany, etc.
Interface TypeScript
Describe la forma que debe tener un objeto en el frontend. Sirve para chequeo estático y autocompletado.
DTO del backend
Contrato que la API decide exponer. En un sistema real, el modelo TS debería alinearse principalmente con este contrato.
Dato simulado (mock)
Objeto local que respeta el mismo modelo TS y permite construir la UI antes de consumir la API.

Importante:  una interface TypeScript no crea una tabla ni existe en PostgreSQL. Es una ayuda del compilador/editor para detectar inconsistencias antes de ejecutar la aplicación. Los archivos con JSX deben usar extensión .tsx.

5. Crear los modelos Cliente y Vehiculo
5.1 Modelo Cliente
Crea src/features/clientes/models/Cliente.ts:
export interface Cliente {
  id: number;
  nombre: string;
  apellido: string;
  documento: string;
  telefono: string;
  email: string;
  activo: boolean;
}

Los nombres de atributos son didácticos. Si tu backend ParkFlow360 usa otros nombres exactos, conserva el concepto y alinea los modelos con el contrato real que expone tu API.
5.2 Modelo Vehiculo
Crea src/features/vehiculos/models/Vehiculo.ts:
export interface Vehiculo {
  id: number;
  placa: string;
  marca: string;
  modelo: string;
  anio: number;
  color: string;
  clienteId: number;
  activo: boolean;
}

Relación 1:N:  un Cliente puede poseer varios Vehículos. En los mocks usaremos clienteId para señalar a qué cliente pertenece cada vehículo. Más adelante, al consumir la API, podremos adaptar este modelo al JSON real que devuelva Spring Boot.

7. Construir las tablas
La página será responsable de seleccionar/preparar datos y el componente de tabla será responsable de mostrarlos. Así practicamos separación de responsabilidades y props.
7.1 ClienteTable.tsx
import type { Cliente } from '../models/Cliente';

interface ClienteTableProps {
  clientes: Cliente[];
}

export default function ClienteTable({ clientes }: ClienteTableProps) {
  if (clientes.length === 0) {
    return <div className="empty-state">No hay clientes registrados.</div>;
  }

  return (
    <div className="table-card">
      <div className="table-responsive">
        <table className="data-table">
          <thead>
            <tr>
              <th>ID</th>
              <th>Cliente</th>
              <th>Documento</th>
              <th>Teléfono</th>
              <th>Email</th>
              <th>Estado</th>
            </tr>
          </thead>
          <tbody>
            {clientes.map((cliente) => (
              <tr key={cliente.id}>
                <td>{cliente.id}</td>
                <td>{cliente.nombre} {cliente.apellido}</td>
                <td>{cliente.documento}</td>
                <td>{cliente.telefono}</td>
                <td>{cliente.email}</td>
                <td>
                  <span className={`status-badge ${cliente.activo ? 'status-active' : 'status-inactive'}`}>
                    {cliente.activo ? 'Activo' : 'Inactivo'}
                  </span>
                </td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </div>
  );
}

Qué debes poder explicar
ClienteTableProps obliga a que la prop clientes sea un arreglo de objetos Cliente.
La desestructuración { clientes } extrae esa prop dentro del componente.
map() transforma cada Cliente en un <tr>.
key={cliente.id} ofrece a React una identidad estable para cada fila.
El operador ternario decide el texto y la clase visual del estado.
El retorno temprano muestra un estado vacío cuando no existen registros.
7.2 VehiculoTable.tsx
import type { Cliente } from '../../clientes/models/Cliente';
import type { Vehiculo } from '../models/Vehiculo';

interface VehiculoTableProps {
  vehiculos: Vehiculo[];
  clientes: Cliente[];
}

export default function VehiculoTable({ vehiculos, clientes }: VehiculoTableProps) {
  const obtenerNombreCliente = (clienteId: number) => {
    const cliente = clientes.find((item) => item.id === clienteId);
    return cliente ? `${cliente.nombre} ${cliente.apellido}` : 'Sin cliente asociado';
  };

  if (vehiculos.length === 0) {
    return <div className="empty-state">No hay vehículos registrados.</div>;
  }

  return (
    <div className="table-card">
      <div className="table-responsive">
        <table className="data-table">
          <thead>
            <tr>
              <th>Placa</th>
              <th>Marca / Modelo</th>
              <th>Año</th>
              <th>Color</th>
              <th>Cliente</th>
              <th>Estado</th>
            </tr>
          </thead>
          <tbody>
            {vehiculos.map((vehiculo) => (
              <tr key={vehiculo.id}>
                <td className="plate-cell">{vehiculo.placa}</td>
                <td>{vehiculo.marca} {vehiculo.modelo}</td>
                <td>{vehiculo.anio}</td>
                <td>{vehiculo.color}</td>
                <td>{obtenerNombreCliente(vehiculo.clienteId)}</td>
                <td>
                  <span className={`status-badge ${vehiculo.activo ? 'status-active' : 'status-inactive'}`}>
                    {vehiculo.activo ? 'Activo' : 'Inactivo'}
                  </span>
                </td>
              </tr>
            ))}
          </tbody>
        </table>
      </div>
    </div>
  );
}

¿Qué representa find() aquí?  busca el Cliente cuyo id coincide con vehiculo.clienteId. Es una forma sencilla de visualizar la relación mientras trabajamos con arreglos locales. Si no encuentra coincidencia, se muestra “Sin cliente asociado”.

8. Integrar las tablas en las páginas
8.1 ClientesPage.tsx
import ClienteTable from '../components/ClienteTable';
import { clientesMock } from '../data/clientes.mock';

export default function ClientesPage() {

Observa que la página conoce el origen de los datos simulados y se los entrega a ClienteTable mediante la prop clientes. La tabla no importa clientesMock directamente.

10. Flujo mental que debe defender el estudiante
clientes.mock.ts
      ↓  exporta Cliente[]
ClientesPage.tsx
      ↓  pasa clientes={clientesMock}
ClienteTable.tsx
      ↓  recibe Cliente[] mediante props
clientes.map(...)
      ↓  transforma cada objeto en <tr>
JSX
      ↓
React actualiza el DOM
      ↓
El navegador muestra la tabla

Para Vehículos el flujo es equivalente, con una diferencia: VehiculoTable también recibe clientesMock para convertir clienteId en un nombre visible mediante find().
